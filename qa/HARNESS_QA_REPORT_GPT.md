### 1. 검증한 코드와 제출 코드가 다름

- `/tmp/qa_GPT/qa_work/core_tests.py`의 `race` 실험: 자체 시험 답안을 p10으로 복사했다. 첫 무작위 입력 생성 시점에 외부 과정이 `p10.cpp`를 `int main(`으로 바꾸고 검증을 계속했다.
- `timeout 300 scripts/final_gate.sh qa_work/fixtures/race/p10 --fuzz 200 --seed2 99 --no-cov` → `PASS`, 제출 복사 참.
- 보고된 해시 `8da217921045486d`, 실제 제출 해시 `1e3c5e0c6ac00eee`. `timeout 30 g++ -std=c++20 -O2 -o qa_work/race_submit submit/p10.cpp` → 종료 코드 1, `error: expected primary-expression at end of input`.
- 여러 창에서 수정·제출이 겹칠 때 생길 수 있다. 고침 예: `src_bytes`를 임시 파일로 고정하고 끝까지 그것만 빌드·복사한다.

### 2. 미해결 교차 확인이 승인 없이 풀림

- 실제 모델을 부르지 않고 자체 시험의 6개 사례에 QA 모의 출력 1개를 넣었다. 다른 출력은 `xcheck.sh ingest`로 받았다.
- `RESOLVED.md`에 `| 01_example | 결정 D99 에 달림 | 두 가지 읽기가 남아서 사람의 결정을 기다린다 |`를 넣고, 결정 카드에는 답을 적지 않았다.
- `timeout 300 scripts/final_gate.sh qa_work/fixtures/pending_decision/p9 --fuzz 200 --seed2 99 --no-cov` → `PASS`, 승인 문자열 없이 제출 복사.
- 리허설에도 같은 형식이 있다: `problems/p1/xcheck/RESOLVED.md:5`\~7. `AI_USAGE.md`에는 카드 D2의 사람 답보다 앞선 PASS가 남아 있다. 이 실험은 모델의 정답 능력이 아닌 판정 경로 시험이다.
- 시각 근거: `AI_USAGE.md:65` 카드 제시 15:12:51 → `:70` PASS 15:15:14 → `:104` 사람의 D2 선택 16:51:15.
- `--accept`는 빈 말이 아니면 받는다(`verify.py:1010`). 다만 가짜 승인 기록을 발견한 것은 아니다. 사람은 실제로 대안·시간을 물었다(`submit/ai_usage/02_human_inputs.md:20`). 문제는 미결정이 PASS로 빠져 **승인을 물을 대상에서 사라지는 것**이다.

### 3. 옮겨 적기 검사에 안 보이는 오류

- `timeout 120 python3 -u qa_work/intake_tests.py`의 세 비교는 모두 종료 코드 0, `옮겨 적기 확인: 같다`였다.
- 바꾼 내용: `100 이하`를 `100 미만`으로 바꾸고 “거부된 주문은 유량에 세지 않는다”를 삭제. 또 `수량 한도 10, 시간 창 20`을 `수량 한도 20, 시간 창 10`으로 바꿈.
- 검사는 숫자·대문자 낱말의 **개수**를 센다. 순서, 부등호, 부정문은 보지 않는다. “같다”를 원문 전체가 같다는 뜻으로 읽으면 안 된다.
- 워드 수식 `가격 > 100 이면 REJ`도 추출에서 사라졌다. 추출문에 글이 남아 있으면 현재 접수 절차는 두 번째 읽기를 강제하지 않는다.
- `.claude/skills/intake/SKILL.md:30`, `:49`를 고쳐 “추출문이 멀쩡해 보여도 수식·그림이 있으면 원본을 다시 읽는다”로 만든다. 문장 비교는 원본의 해당 문제 구간을 먼저 정한 뒤 한다.

### 5. 0건·미검증을 PASS로 세는 길

- `timeout 300 scripts/mutants.sh qa_work/fixtures/empty_checks/p9 --budget 0 --fuzz 0 --max 5` 후 검증 → `변형 0개 중 0개를 잡았다`, 결과 `PASS`.
- 같은 검증에 `0행 모두 테스트가 있다`, `gen2.py … 0회 … 오류로 중간에 뺐다`가 함께 있어도 최종 `PASS`였다.
- 별도 실험은 `known_fail/lost.in`만 두고 `.out`을 빼었다. `기대 출력이 없는 것: lost.in`을 적지만 최종은 `PASS`다.
- 반면 무작위 0회, 검사기·생성기·독립 구현을 모두 빼기, 교차 확인 전체 누락은 조건부로 막혔다(자체 시험 사본 결과).
- 추가 실험: 6개 입력 끝에 빈 줄 100개씩을 붙였다. 원래 답과 기대 출력은 그대로인데 입력 지문은 바뀌고 모두 80줄을 넘는다. 결과는 `정답 사례 교차 확인 … PASS … 6개 중 0개 … 커서 뺀 사례 6개`, 최종 `PASS`였다.
- 고장 난 gen2와 변형 0개도 따로 검증했다: `only_broken_gen2 0 PASS []`, `only_zero_mutants 0 PASS []`(마지막 `[]`는 조건부 사유 없음). `HARNESS.md:41`의 “위 검사를 모두 돌렸고”는 현재 동작보다 강한 표현이다.

### 6. FAIL 뒤에도 남는 옛 제출 파일

- 복사본 p2의 맨 끝에 `THIS_IS_NOT_VALID_CPP`를 붙이고 `timeout 30 scripts/final_gate.sh p2` → 종료 코드 1, `FAIL`.
- 이어 `COTEST_SKIP_COLLECT=1 timeout 120 scripts/pack.sh` → 종료 코드 0. `submit/p2.cpp`를 답안으로 올리고 `걸리는 것이 없다`고 썼다. 현 소스와 제출 파일은 달랐다.
- 수집을 건너뛴 것은 실제 개인 기록을 더 읽지 않기 위해서다. 답안 목록·해시 판정에는 관여하지 않는다. 실험 뒤 복사본 소스는 되돌렸다.

### 7. 메모리 제한 초과를 승인 없이 제출

- 자체 시험 답안을 p12로 복사하고 30,000번째 줄에서 `vector<unsigned char>`에 300MiB를 넣었다. 출력 규칙은 바꾸지 않았다.
- `timeout 300 scripts/final_gate.sh qa_work/fixtures/memory/p12 --fuzz 200 --seed2 99 --no-cov` → `큰 입력 메모리: 확인, 310MB`, `판정: PASS`, `submit/p12.cpp 로 복사했다`.
- 고정 1초라는 이미 알려진 한계와 별개다. 메모리 경고는 256MB에서 뜨지만 조건부는 **1024MB 초과**에서만 걸린다. 실제 안내문은 256MB다.

### 8. 동시 기록 수집의 충돌

- `timeout 120 python3 -u qa_work/log_tests.py`: 개인 기록 대신 `/tmp/qa_GPT/qa_work/log_fixture/`에 만든 가짜 기록을 썼다. 수집 함수 자체는 원래 코드다.

### 9. 기록의 범위와 이름 충돌

- 같은 모의 기록 시험에서 출력: `unrelated_codex_copied True`, `old_private_copied True`, `same_name_agent_sources 2 collected 1`.

### 10. 한 파일 제출의 내용 누락

- 모의 Claude 기록에 3,000자가 넘는 `Write` 도구 입력을 넣었다. `usage_export.sh --raw <모의 기록> --formats txt` → 끝 표식 없음, `자 줄임` 있음. 같은 명령에 `--full` → 끝 표식 있음, 줄임 없음.

2. 메일 본문의 정정과 첨부의 옛 문장 중 AI가 옛 것을 고를 수 있다. 발견 4의 파일 덮어쓰기는 재현했지만, 실제 AI에게 정정 메일을 읽혀 선택하게 하지는 않았다.

## 4. 질문별 답 (A \~ G, 질문마다 3줄 이하)

- **A:** 11·12. 필수 카드 한도, 중복의 범위, 체결가가 빠진 실제 체결이 갈림이다. 다섯 사례의 새 추천·평가 위험, 추가 조합 4개, stderr 분리 실험을 11에 적었다. T39는 파기·정정 조건을 붙여야 한다.
- **B:** 1·2·5·7. 같은 오독을 정답으로 바꾸는 검사는 없다. 버그 네 종류는 모두 FAIL이었으나 마지막 줄 버그는 고정 사례를 통과했다(6절). 승인 자체가 형식적이라는 증거는 없고, 승인 대상이 빠지는 버그가 있다.
- **C:** 3·4·8·13. 추출 누락·덮어쓰기·동시 수집·병렬 예산을 재현했다. 5문제와 건너뛴 번호는 표시된다. AI 응답 실패와 다른 문제 형식은 13의 대비책·미검증 범위를 따른다.
- **D:** 8·9·10·14. 기록 누락·사담 혼입·축약된 한 파일 제출 경로가 있다. HARNESS의 “모든 검사”, “첫 코드 안 봄”은 실제 범위로 좁혀야 한다. 평가자가 어떤 인상을 받을지는 판단하지 않았다.
- **E:** 11·14. p2 D1을 한 표로 다시 썼다. p2 D3의 AI 단독 허용은 새 규칙과 다르고, C++ 나눗셈 방식이나 실제 출력의 정답 여부를 사람에게 고르게 해서는 안 된다.
- **F:** 실행으로 재현한 버그는 1\~10·13에 합쳤다. 별도 중복 발견으로 세지 않았다.
- **G:** 13. 근거 있는 절감 대상은 16분 24초·17분 3초의 시작 지연, 끝에 몰린 승인 설명이다. 성능 문제를 실제 찾은 리뷰와 최종 검증은 줄일 근거가 없다.

## 5. 고치지 말아야 할 것

- 테스트 기대값·독립 구현을 답안에 맞추지 않는 원칙을 유지한다. 아래 네 버그 실험은 그 파일들을 그대로 둔 채 검증기가 잡았다.
- `from_chars`, 64비트 곱셈 전 검사, 정수 비율 비교, 경고·ASan·UBSan을 빼지 않는다. 넘침 주입은 UBSan이 구체적인 식까지 잡았다.
- 원본 대화 ZIP을 유지한다. 읽기 쉬운 문서의 축약을 보완하는 근거다. 지금 새 기록 시스템으로 전면 교체하지 않는다.
- `log_step.sh:18`의 잠금은 유지한다. 모든 git 명령이 보호되는 것은 아니며, 검토 지침상 동시 커밋 실험은 하지 않았다. `git add -A`가 다른 창의 변경도 포함할 수 있다는 점은 운영 때 유의한다.
- 원문·명시적 결정 우선, 추천으로 계속 풀기, 풀이와 독립 검증을 동시에 진행하는 절차를 유지한다. 수정 대상은 그 결과를 제출하는 판정과 기록의 빈틈이다.

## 7. 내가 틀릴 수 있는 곳

- 발견 1·8은 충돌 순서를 일부러 고정했다. 가능한 실패를 증명하며, 실전에서 얼마나 자주 생기는지는 측정하지 않았다. 문제마다 별도 창을 써도 최종 관문·훅은 겹칠 수 있다.
- 발견 7은 리허설의 256MB 제한 기준이다. 과제 안내문이 다른 제한을 주면 그 값으로 바꿔야 한다. 큰 입력 성능은 이 PC의 측정이며 평가 PC를 재현하지 않았다.
- 발견 10은 글·워드·웹 문서 하나만 제출할 때의 문제다. 원본을 포함한 기본 ZIP을 내면 같은 누락으로 보지 않는다.
- 새 추천이 비공개 테스트의 정답과 같다고 보장하지 않는다. stderr를 stdout에 합치는 평가기는 시험하지 않았다. 안내문대로 stdout만 비교하는 경우의 분리는 실행했다.
- TRAPS의 모든 거래소 관례를 외부 규격과 다시 대조하지 않았다. 12는 사전 내부의 수량 모순이고, 11의 추가 조합은 적용 범위를 보완할 제안이다.
- 실제 AI 한도 오류·비정상 종료, VS Code의 곁 질문 저장소, Windows 메일 발송은 실행하지 않았다. 다른 검토자의 보고서와 과거 QA 기록은 끝까지 읽지 않았다.
- DOCX 실험은 추출기가 읽는 XML만 넣은 최소 파일이다. 수식 누락은 재현했지만 Word 프로그램에서 파일을 여는 시험은 하지 않았다.
