# cotest 사용 안내

C++ 코딩 과제(주제: 주문 관리 시스템)를 AI와 함께 풀고, 사람이 코드를 한 줄씩 읽지 않고도 검증하는 작업 공간이다.

## 누가 무엇을 하나

주문 관리 시스템에 빗대면 이렇다.

| 누구 | OMS에 빗대면 | 하는 일 |
|---|---|---|
| Claude Code (작업자) | 주문을 내는 쪽 | 요구사항 정리, 테스트, 구현, 검증 실행, 보고 |
| Codex (다른 회사 모델) | 독립된 대사(맞춰 보기) 담당 | 애매한 점 찾기, 따로 쓴 구현과 입력 생성기, 정답 사례의 출력을 따로 구하기, 리뷰 |
| 스크립트 | 주문 전 위험 점검 | 판정을 낸다. PASS, 조건부, FAIL |
| **사람** | **위험 관리자** | 아래 세 가지 |

**사람이 하는 세 가지** (AI가 대신하지 않는다)

1. **뜻을 정한다.** 문제에 없고 관례가 갈리는 것을 고른다(결정 카드). 카드에는 선택지마다 "추가로 드는 시간"이 적혀 있다. 모르겠으면 "추천대로"라고 답해도 된다.
2. **묻는다.** "이러면 어떻게 되지?"가 떠오르면 `/probe p1 <상황>` 으로 바로 돌려 본다. 안 떠오르면 안 해도 된다.
3. **운영한다.** 현황판을 보고 어느 문제에 시간을 더 쓸지, 알려진 한계를 안고 제출할지 정한다.

**사람이 하지 않는 것**: 기대 출력이 맞는지 눈으로 확인하는 일, 옮겨 적은 문제를 원본과 맞춰 보는 일. 제한 시간 안에 사람이 할 수 있는 검사가 아니라서 뺐다. 대신 이렇게 한다.

| 예전에 사람이 보던 것 | 지금 |
|---|---|
| 기대 출력이 맞는가 | Codex 가 입력과 문제만 보고(기대 출력도 답안도 못 본 채) 출력을 손으로 따로 구한다. 기계가 한 글자씩 견준다. 다르면 AI가 원문으로 가리고 근거를 적는다 |
| 옮겨 적은 문제가 원본과 같은가 | 스크립트가 숫자와 대문자 낱말을 원본에서 꺼낸 글과 견준다. 그림이나 스캔한 PDF 는 다른 에이전트가 한 번 더 읽어 견준다 |

## 한 장 요약

| 순서 | 내가 치는 것 | AI가 하는 일 | 내가 하는 일 |
|---|---|---|---|
| 0 | (다른 터미널) `scripts/board.sh --watch` | | 현황판을 띄워 둔다 |
| 1 | 받은 파일을 `inbox/` 에 그대로 넣고 `/intake` | 받은 자료를 풀고 분류한다(압축, 워드, PDF, 메일 본문). 시계를 켜고, 문제마다 요구사항·예외 표·결정을 쓴다 | 그동안 문제를 직접 읽는다 |
| 2 | 문제마다 **새 대화창**에서 `/solve p1`, `/solve p2` … | 테스트 → 정답 사례 교차 확인 → 구현 → 독립 구현 비교 → 테스트의 힘 재기 → 리뷰 → 보고. 카드의 답을 기다리지 않고 추천안으로 먼저 간다 | 풀이가 도는 동안 카드를 읽고, **풀이가 돌고 있어도 그대로** 그 문제의 창에 답을 입력해 보낸다(`D2: A` 또는 `추천대로`) |
| 3 | (선택) `/probe p1 <상황>` | 상황을 입력으로 바꿔 두 구현에 넣어 보고 출력을 보여 준다 | 출력이 맞는지 말한다 |
| 4 | `/finish` | 최종 관문, AI 사용 내역, 제출 묶음. 안내문이 요구한 형식에 맞춰 낼 파일을 정한다 | 조건부인 문제를 낼지 정한다 |
| 5 | (터미널) `scripts/pack.sh` | | 보내기 직전에 한 번 더 묶는다. `submit/SUBMIT_LIST.md` 에 적힌 파일을 메일에 첨부해 직접 보낸다 |
| 6 | `/explain p1` | 제출 뒤 코드 설명서 | 답안을 설명할 수 있게 읽어 둔다 |

**카드의 답을 기다리느라 멈추지 않는다.** 연습 2에서는 40분 가운데 24분이 답을 기다린 시간이었다. 이제 `/intake` 가 카드를 보여 주면 곧바로 문제마다 대화창을 열어 `/solve` 를 시작하고, 카드는 풀이가 도는 동안 읽는다.

## 흐름

```
받은 파일 ──▶ inbox/ ──▶ /intake ─┬─▶ 전처리: 풀기·글 꺼내기·분류 (inbox/INDEX.md, SUBMIT_RULES.md, AI_GUIDELINE.md)
                                  ├─▶ 문제마다 PROBLEM (옮겨 적기를 기계가 원본과 견줌) / SPEC / EDGE / DECISIONS (+ Codex: 애매한 점)
                                  └─▶ 결정 카드를 한 번에 보여 줌 ──▶ 사람이 읽기 시작

문제마다 새 대화창: /solve pN
   Codex(백그라운드) ①: 독립 구현 alt.cpp + 입력 생성기 gen2.py        ◀── 답안을 보지 않고 씀
   Claude: 테스트(입력 + 손으로 구한 기대 출력)
   Codex(백그라운드) ②: 같은 입력의 출력을 따로 구함 xcheck/*.out      ◀── 기대 출력도 답안도 보지 않고 씀
   Claude: 효율 계획 ─▶ 구현 ─▶ gen.py, check.py
        ─▶ verify.sh (기대 출력 = 답안 = 독립 구현 = 따로 구한 출력인지, 무작위 1000회, 큰 입력 시간 …)
        ─▶ 다른 곳을 원문으로 가리기 ─▶ 변형 시험·실행 안 된 줄 ─▶ Codex 리뷰 ③(재현되는 지적만) ─▶ REPORT
   사람: 카드에 답함 / (선택) /probe 로 "이러면?" 확인 / 현황판 보고 시간 배분

/finish ─▶ final_gate (PASS 만 submit/ 으로. 조건부는 사람의 승인)
        ─▶ pack.sh ─▶ submit/pN.cpp + ai_usage_logs.zip + ai_usage/(여러 형식) ─▶ 안내문이 요구한 형식으로 골라 사람이 메일로 보냄
```

## 시작하기

```bash
cd ~/cotest && code .
```

모델은 `scripts/models.sh fable`(Claude Fable 5.2 + Codex gpt-6-astra) 또는 `scripts/models.sh opus`(Claude Opus 5.5 + Codex gpt-6.1-sol)로 정한다. 인자 없이 `scripts/models.sh` 를 치면 지금 설정과 **실제로 쓰인 모델**을 보여 준다. 바꾼 뒤에 새로 연 대화창부터 적용된다.

VS Code에서 Claude Code 창을 연다. 터미널을 하나 열어 현황판을 띄운다.

```bash
scripts/board.sh --watch
```

받은 파일을 **받은 그대로** `inbox/` 에 넣고 `/intake` 를 친다. 메일 본문에 문제가 있으면 본문을 글 파일로 저장해 넣거나 대화창에 붙여 넣는다. 압축, 워드, PDF, 한글(hwpx), 그림은 그대로 넣으면 된다. 옛 한글 파일(`.hwp`)만 PDF 로 저장해서 넣는다.

윈도우에서 내려받은 파일을 넣는 법: VS Code 왼쪽 파일 목록의 `inbox` 폴더 위로 파일을 끌어다 놓는다. 또는 윈도우 탐색기 주소창에 `\\wsl.localhost\Ubuntu-24.04\home\<리눅스 사용자>\cotest\inbox` 를 넣어 연다. 메일 본문은 `inbox` 를 오른쪽 클릭 → 새 파일 → `mail.txt` 를 만들어 붙여 넣고 저장한다. 탐색기로 옮기면 `이름:Zone.Identifier` 같은 파일이 따라올 수 있다. 접수가 알아서 건너뛴다.

**진행 중의 질문은 기록이 남는 곳에서 한다.** 판단에 필요한 것을 물을 때는 대화창을 하나 더 열어 `/ask p1 D3 의 A 와 C 는 뭐가 달라?` 처럼 묻는다(그 창에서 이어서 물어도 된다). 곁 질문(`/btw`, 옆에 뜨는 작은 대화)은 대화 기록 파일에 들어가지 않는다. `collect_logs` 가 VS Code 저장소에서 따로 모으고, 빠진 것이 있으면 `submit/SUBMIT_LIST.md` 의 "보내기 전에 확인할 것"에 나온다.


문제 설계 메모와 비공개 테스트는 이 저장소에 넣지 않았다(풀이 중에 AI가 보지 못하게 폴더 밖에 둔다). 끝난 뒤 사람이 평가를 돌린다.

## 현황판 읽는 법

| 칸 | 뜻 |
|---|---|
| 단계 | 접수 → 요구사항·예외 표 → 테스트 → 구현 → 독립 구현 → 검증 → 리뷰 → 보고 |
| 일한 시간 / 답 대기 | AI가 일한 시간과, 내 답을 기다린 시간 |
| 마지막 판정 | PASS, 조건부, FAIL. "(옛 파일)"은 검증 뒤에 코드가 바뀌었다는 뜻 |
| 정답 사례 (다른 모델 확인) | 전체 사례 수와, 그중 Codex 가 따로 구한 출력과 같았던 수. "다름 n"이 있으면 AI가 가리는 중이다 |
| 변형 잡음 | 코드를 일부러 조금 바꾼 판을 테스트가 몇 개 잡았나 |
| 지금 사람이 할 일 | 여기에 뭔가 있으면 내 차례다 |

## 검증 표 읽는 법 (`VERIFY.txt`)

| 검사 | 무엇을 보나 |
|---|---|
| 평가 명령 빌드, 경고 없음 | 평가와 같은 명령으로 컴파일되는가. 컴파일러 경고가 없는가 |
| 1층 정답 사례 | 기대 출력을 아는 입력에서 한 글자도 다르지 않은가 |
| 정답 사례 교차 확인 (다른 모델) | 기대 출력이, Codex 가 입력과 문제만 보고 따로 구한 출력과 같은가. 기대 출력과 답안을 같은 AI가 썼으므로 문제를 잘못 읽으면 둘이 함께 틀린다. 그것을 잡는다. 다른 사례는 원문으로 가려 근거를 적어야 조건부가 풀린다 |
| 정답 사례에서 독립 구현의 출력 | Codex 가 따로 쓴 구현도 정답 사례에서 기대 출력을 그대로 내는가 |
| 예외 표와 테스트의 대응 | 예외 표의 모든 행에 테스트가 있는가 |
| 메모리·정의되지 않은 동작 | 배열 밖 접근, 정수 넘침 같은 실행 중 오류가 없는가 |
| 2층 불변식 검사 | 어떤 입력에서도 지켜져야 할 규칙이 지켜지는가 |
| 검사기의 힘 | 정답 출력을 일부러 틀리게 바꾼 것을 검사기가 몇 개나 잡는가 |
| 3층 무작위 입력 + 독립 구현 비교 | 무작위 입력 1000개에서 Codex가 따로 쓴 구현과 출력이 같은가. 입력은 Claude 의 생성기와 Codex 의 생성기를 번갈아 쓴다 |
| 무작위 입력의 치우침 | 무작위 입력에서 거의 나오지 않는 출력 종류. 그 갈래는 덜 시험된 것이다 |
| 큰 입력 실행 시간 | 최대 크기 입력(평범한 것과 가장 느린 모양)이 1초 안에 끝나는가. 줄당 몇 마이크로초인지도 적는다. 입력이 2배일 때 시간이 3배를 넘으면 알려 준다 |
| 큰 입력 메모리 | 같은 입력에서 최대 메모리가 몇 MB 인가(줄당 몇 바이트). 256MB 를 넘으면 알려 주고, 1GB 를 넘으면 조건부 |
| 실행되지 않은 줄 | 어떤 시험에서도 한 번도 실행되지 않은 코드 줄. 검증되지 않은 줄이다 |
| 변형 시험 | 비교 연산자를 바꾼 판을 테스트가 잡는가. 살아남은 것은 시험되지 않은 경계다 |
| 알려진 한계 | 고치지 못하고 남긴 반례(`known_fail/`)가 있는가 |

판정은 셋이다. **PASS**: 다 돌렸고 실패가 없다. **조건부**: 실패는 없지만 내가 알고 받아들여야 할 것이 있다. **FAIL**: 실패가 있다.
조건부인 문제는 내가 승인해야 `submit/` 으로 복사된다.

## 무엇을 제출하나

`scripts/pack.sh` 가 `submit/` 에 만들어 주는 것을 메일에 첨부한다. 목록은 `submit/SUBMIT_LIST.md` 에도 적힌다.

| 첨부 | 내용 |
|---|---|
| `submit/p1.cpp`, `p2.cpp` … | 답안. 문제마다 파일 하나 |
| `submit/ai_usage_logs.zip` | AI 사용 내역 묶음: `AI_USAGE.md`(쓴 도구와 모델, 사람이 한 일), 대화 기록 전체(원본 기록과, 거기서 기계로 만든 읽기 쉬운 기록), `HARNESS.md`, 문제별 결정·보고서·검증 결과·테스트 |

- 대화 기록은 반드시 낸다. 과제 안내문이 "전체 대화 기록과 사용한 모델"을 요구했고, 밝히지 않은 사용은 인정되지 않는다.
- 대화창마다 `/export` 를 칠 필요가 없다. `pack.sh` 가 원본 기록(`logs/raw/`)에서 읽기 쉬운 대화 기록을 만든다.

**제출 형식이 아직 정해지지 않았다.** 그래서 기록은 한 번만 모으고, 형식은 마지막에 고른다. `pack.sh` 를 돌리면 `submit/ai_usage/` 에 같은 내용이 여러 형식으로 풀린다.

| 요구받은 형식 | 낼 파일 |
|---|---|
| 정해진 형식 없음 / 압축 파일 | `submit/ai_usage_logs.zip` |
| 글 파일 하나, 워드 문서 하나 | `scripts/usage_export.sh --full` 을 돌린 뒤의 `ai_usage/transcript_all.txt`, `transcript_all.docx` (`--full` 없이 만든 것은 긴 코드와 출력이 줄여져 있어 "전체 대화"가 아니다) |
| PDF | `ai_usage/transcript_all.html` 을 브라우저에서 열어 인쇄 → PDF 로 저장 |
| 표(엑셀) | `ai_usage/03_interactions.csv`(주고받은 일 한 줄씩: 시각, 문제, 도구, 모델, 누가 시작, 지시, 결과) |
| 문제별로 따로 | `ai_usage/by_problem/p1.md` … |
| 내가 무엇을 입력했는지 | `ai_usage/02_human_inputs.md` |
| 쓴 도구와 모델 | `ai_usage/01_tools_and_models.md` |
| 용량 제한 | `scripts/usage_export.sh --zip full --max-mb 20` (넘으면 나눠 담는다) |
| 그 밖의 양식 | `/finish` 가 안내문을 읽고 위 파일을 재료로 그 형식을 만든다. 양식 파일을 받았으면 `inbox/` 에 넣는다 |

- 안내문의 요구는 접수 때 `SUBMIT_RULES.md` 와 `AI_GUIDELINE.md` 에 옮겨지고, `/finish` 가 그것을 다시 읽어 낼 파일을 정한다.
- 읽기 쉬운 기록에서는 긴 도구 출력이 줄여져 있다(줄인 곳마다 표시가 있다). 줄이지 않은 전체는 `scripts/usage_export.sh --full` 이나 원본 기록이다.

## 폴더

| 폴더·파일 | 내용 |
|---|---|
| `inbox/` | 받은 과제 자료를 그대로 넣는 곳. `_SCAN.md`(파일 목록), `INDEX.md`(분류), `_text/`(꺼낸 글), `_unpacked/`(푼 압축) |
| `SUBMIT_RULES.md`, `AI_GUIDELINE.md` | 과제 안내문에서 옮긴 제출 규칙과 AI 사용 지침 (접수 때 생긴다) |
| `problems/pN/` | 문제별 작업 폴더. `PROBLEM.md`(원문), `given/`(받은 원본과 예제), `SPEC.md`, `EDGE.md`(예외 표), `DECISIONS.md`(결정, 효율 계획), `tests/`, `xcheck/`(다른 모델이 따로 구한 출력), `pN.cpp`, `alt.cpp`(독립 구현), `gen.py`·`gen2.py`(입력 생성기), `VERIFY.txt`, `MUTANTS.txt`, `REPORT.md`, `EXPLAIN.md` |
| `submit/` | 최종 관문을 통과한 답안, 제출 묶음, `ai_usage/`(AI 사용 내역의 여러 형식), `SUBMIT_LIST.md` |
| `knowledge/TRAPS.md` | 실무 함정 사전. 미리 읽어 둔다 |
| `knowledge/PERF.md` | 속도·메모리 사전. 자료구조를 고를 때(효율 계획), 큰 입력을 만들 때, 리뷰할 때 쓴다. 이 PC 에서 잰 숫자가 들어 있다 |
| `CHECKLIST.md` | 입력 오류 점검표 |
| `AI_USAGE.md`, `logs/` | AI 사용 내역과 원본 기록. `logs/MANIFEST.md` 가 목록이다 |
| `HARNESS.md` | 이 작업 방식의 설명(제출할 때 함께 낸다) |
| `BOARD.md` | 현황판의 마지막 모습 |
| `practice/` | 연습 문제와 리허설 문제 (`practice/README.md`) |

## 도구가 말을 듣지 않을 때

| 증상 | 할 일 |
|---|---|
| Codex 호출이 `CODEX_FAILED` | AI가 대비책(새 Claude 에이전트)을 쓴다. 독립성이 약해진다는 점이 보고서에 적힌다 |
| Claude Code가 멈춤 | 대화창을 새로 열고 `scripts/board.sh` 결과를 보여 준 뒤 `/solve p1` 을 다시 친다. 상태는 파일에 있다 |
| 한 문제에 시간이 너무 감 | 현황판의 "시간 예산 초과"를 보고 "p1 중단, p2 로"라고 말한다 |
| 검증이 계속 FAIL | 같은 실패가 세 번이면 AI가 멈추고 보고한다. 마지막으로 통과한 판을 낼 수 있다 |

## 실전 30분 전

1. `python3 scripts/selftest.py --quick` 이 "통과"인지 본다.
2. 연습 결과를 `scripts/archive_run.sh 이름` 으로 치운다. `problems/`, `submit/`, `inbox/`, `logs/` 가 비고 `AI_USAGE.md` 가 빈 양식이 된다. 지난 연습의 대화 기록이 제출 묶음에 섞이지 않게 하려는 것이다.
3. `scripts/models.sh` 로 모델 설정을 확인하고 Codex 로그인을 확인한다. PDF 로 올 때를 대비해 `pdftotext -v` 가 되는지 본다(안 되면 `sudo apt install poppler-utils`. 없어도 진행은 되지만 옮겨 적기 확인이 "두 번째 읽기"로 느려진다).
4. 현황판 터미널을 띄운다.
5. `knowledge/TRAPS.md` 의 굵은 글씨 항목과 맨 아래 "문제에 없으면 사람에게 올릴 것"을 한 번 읽는다.
