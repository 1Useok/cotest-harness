# 04. 외부 리뷰 처리 내역

대상은 커밋 `7861d1c`(하네스 v6 + 환경 안내 한 줄)입니다. 하네스를 만든 모델과 구현하는 모델이 모두 Claude 라는 점이 구조적 약점이라고 판단해, 제작 과정에 참여하지 않은 두 모델에게 하네스 전체의 리뷰를 맡겼습니다. 두 리뷰어는 서로의 보고서를 읽지 않았고, 둘 다 복사본에서 명령을 직접 실행해 재현했습니다.

|---|---|---|---|

리뷰 지침(`HARNESS_QA_BRIEF.md`)의 요청은 "실전에서 이 하네스 때문에 결과를 잃거나 제출하지 못하게 되는 경로를, 근거와 함께, 심각한 것부터"였습니다.

리뷰어는 제작 맥락을 모르기 때문에 지적을 그대로 따르지 않고 하나씩 코드와 대조해 반영 여부를 정했습니다. Claude Code(Fable 5.2)가 발견마다 코드와 대조하고, 반영하기로 한 것을 Opus 5.5 하위 에이전트 둘이 고쳐 v7(`b5535c4`)로 커밋했습니다. 아래 판정은 실제로 대조하고 고친 쪽이 매긴 것입니다. "일부"는 지적 가운데 일부만 반영했다는 뜻이고, 반영하지 않은 부분과 그 이유를 같은 칸에 적었습니다.

## 반영하지 않은 제안 (항목 안의 일부 포함)

반영하지 않은 제안에도 이유를 남겼습니다. 위 표와 겹치지만 한곳에 모으면 다음과 같습니다.

- **Gemini F1** "표준 오류 요약을 기본으로 끈다": 끄면 예외를 다시 조용히 넘기는 답이 되므로 채택하지 않았습니다. 같은 항목의 "판단 기준을 독립 구현·교차 검증 지시문에 넣는다"는, 그쪽이 이미 결정 기록을 받으므로 넣지 않았습니다.
- **Gemini F2** "커버리지 미달, 살아남은 변형을 조건부로": 거의 모든 답안이 조건부가 되어 사람의 승인이 형식이 되므로 채택하지 않았습니다.
- **Gemini F4** "단계 기록은 문제별 파일만 커밋": 다른 문제 파일이 섞여도 해가 없고, 나누면 빠지는 파일이 생길 수 있어 유지했습니다.
- **Gemini F7** T6, T180, T183, 체결 통보 가격 항목 보강: 실전 직전에는 사전 범위를 넓히지 않기로 해서 미뤘습니다.
- **GPT 9, Gemini F9** Codex 기록을 작업 폴더로 걸러 내기: 필요한 기록을 빠뜨리는 쪽이 더 위험하다고 보고 운영으로 막았습니다. 모델 이름 불일치(Gemini F9)는 원인이 달랐습니다(위 표).
- **GPT 14** `/probe` 질문 방식: 사람이 스스로 던진 질문의 결과로 의미를 판단하는 것이 설계상 사람의 역할이라고 보고 바꾸지 않았습니다.
- **Gemini F12** 진행 현황판의 대기 시간 집계: 손대지 않았습니다.
