# 탐침: 사람의 질문을 바로 실행해 보기

인자: $ARGUMENTS (예: `p1 취소한 주문에 체결이 또 오면`, `p2 가격이 0인 시세 다음에 주문이 오면`)

사람은 코드를 읽지 않는다. 대신 거래를 아는 사람으로서 "이 상황에서 이렇게 나오는 게 맞나?"를 본다.
이 절차는 그 질문을 30초 안에 실행 결과로 바꿔 준다. 코드를 고치는 절차가 아니다.

## 1. 상황을 입력으로 바꾼다
1. 문제의 `PROBLEM.md`, `SPEC.md` 를 읽고, 사람이 말한 상황을 **가장 짧은 입력**(8줄 이내)으로 만든다. 상황이 두 가지로 읽히면 둘 다 만든다.
2. 실행하기 전에 **원문과 결정 기록에 따르면 무엇이 나와야 하는지**를 먼저 적는다. 원문에 답이 없으면 "원문에 없음"이라고 적는다.

## 2. 실행한다
입력을 파일로 쓰고 `scripts/try.sh pN <파일>` 을 돌린다. 제출 코드와 독립 구현의 출력이 나란히 나온다. 기록은 `problems/pN/probe/` 에 남는다.

## 3. 사람에게 보여 준다
아래 형식으로 메시지에 그대로 싣는다.

```
상황: 취소한 주문에 체결이 또 오면
입력              실제 출력            원문에 따른 기대
O 1 A B 10 100   OK 1                OK 1
X 1              CXL 1 10            CXL 1 10
E 1 1 3 100      ERR 1 OVERFILL      (원문에 없음. D5 에서 AI가 정함)
독립 구현의 출력: 같다
```
그리고 한 줄로 묻는다: "이 출력이 맞습니까? `맞다` / `틀리다: 이유` / `모르겠다`"

## 4. 답에 따라
| 사람의 답 | 할 일 |
|---|---|
| 맞다 | 입력과 출력을 `tests/NN_probe_<짧은이름>.in/.out` 으로 추가하고 `scripts/human_ok.sh pN <이름>` 으로 기록한다. `EDGE.md` 에 행을 추가한다(근거: 사람이 확인) |
| 틀리다 | 원문을 다시 읽는다. 원문이 사람 말과 같으면 제출 코드의 버그다: `/solve` 의 6번대로 고치고 테스트에 추가한다. 원문이 답하지 않으면 결정 카드를 쓴다(선택지에 사람이 말한 동작을 넣는다) |
| 모르겠다 | 원문의 관련 문장을 인용해 보여 주고, 실무 관례가 있으면 `knowledge/TRAPS.md` 의 항목을 한 줄로 알려 준다. 그래도 정할 수 없으면 결정 카드 |
| 제출 코드와 독립 구현의 출력이 다르다 | 사람의 답과 상관없이 `/solve` 의 6번으로 간다 |

끝나면 `scripts/log_step.sh "사람" "pN 탐침: <상황> → <결과>"`.
사례를 추가했으면 `scripts/verify.sh pN` 을 다시 돌린다.

## 사람에게 권할 탐침 (사람이 무엇을 물을지 모를 때 세 개만 고른다)
`knowledge/TRAPS.md` 에서 이 문제에 해당하고 아직 `EDGE.md` 에 없는 항목을 고른다. 없으면 아래에서 고른다.
- 가격이 0이거나 없는 시세 바로 다음에 주문이 오면
- 끝난 주문(전량 체결, 취소)에 체결이나 취소가 또 오면
- 취소와 체결이 엇갈리면
- 정확히 한도와 같은 값이면
- 같은 번호가 두 번 오면
- 보유보다 많이 팔면
- 입력의 맨 첫 줄이 잘못된 줄이면
