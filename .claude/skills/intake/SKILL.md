# 문제 접수 (모든 문제를 한꺼번에)

인자: $ARGUMENTS (없으면 `inbox/` 의 파일 전부. 사용자가 대화에 문제를 붙여 넣었으면 그것. 파일 경로를 주면 그 파일)

목표: 15분 안에 모든 문제의 SPEC, EDGE, DECISIONS 를 만들고, 사람이 정할 것만 한 번에 보여 준다.
먼저 `AGENTS.md` 와 `templates/FORMATS.md` 를 읽는다. **사용자에게 보이는 글은 모두 한국어로 쓴다**(카드, 요약, 진행 알림 모두).

## 0. 시계를 켜고 사람에게 할 일을 준다
1. 타이머가 꺼져 있으면(`logs/EXAM.json` 없음) 사용자에게 제한 시간을 묻지 말고 `scripts/clock.sh start 150` 으로 켠다. 안내문에 다른 시간이 적혀 있으면 그 값으로 다시 켠다. 연습이면 사용자가 말한 시간을 쓴다.
2. 접수를 시작하면서 사용자에게 아래를 **먼저** 보여 준다. 네가 접수하는 동안 사람이 할 일이다.

   > 제가 접수하는 동안 문제를 직접 읽어 주세요. 읽으면서 아래 다섯 가지 가운데 걸리는 것을 메모해 두셨다가, 제 목록에 없으면 말씀해 주세요.
   > 1. 가격이나 수량이 없거나 이상할 때 어떻게 하라고 적혀 있나?
   > 2. 끝난 주문(다 체결됨, 취소됨)에 뭔가 또 오면?
   > 3. 순서가 엇갈리면? (취소와 체결, 주문보다 먼저 온 통보)
   > 4. 한도는 "이하"인가 "미만"인가? 아직 체결 안 된 주문도 세나?
   > 5. 문제에는 없는데 실제 거래라면 당연히 있어야 할 것은?
   >
   > 현황판은 다른 터미널에서 `scripts/board.sh --watch` 로 볼 수 있습니다.

## 1. 받은 자료 정리 (전처리)
과제 자료가 어떤 모양으로 올지 모른다(메일 본문, PDF, 워드, 한글, 압축, 그림, 여러 문제가 한 파일에). 받은 그대로 `inbox/` 에 있다고 보고 아래를 한다.

1. `scripts/inbox_scan.sh` 를 돌린다. 압축과 메일 첨부를 풀고, 워드·한글(hwpx)·웹 문서의 글을 `inbox/_text/` 에 꺼내고, 파일 목록을 `inbox/_SCAN.md` 에 적는다. "사람이 할 일"이 나오면(옛 한글 `.hwp` 등 꺼내지 못한 파일) **바로 사용자에게 알린다**: "이 파일은 제가 읽지 못합니다. PDF 로 저장해 inbox/ 에 넣거나 본문을 붙여 넣어 주세요." 그동안 읽을 수 있는 것부터 진행한다.
2. 모든 파일을 읽는다. PDF 와 그림은 Read 도구로 직접 읽는다(PDF 가 길면 쪽 범위를 나눠서). 꺼낸 글(`_text/`)이 있으면 그것을 읽되, 표나 수식이 깨져 보이면 원본도 본다. `_SCAN.md` 에 "수식·그림을 온전히 꺼내지 못했다"가 있으면 그 파일은 꺼낸 글만 믿지 않는다: **바로 사용자에게** "이 파일을 PDF 로 저장해 inbox/ 에 넣어 주세요"라고 알리고, 받은 PDF 를 Read 로 읽어 견준다.
3. `inbox/INDEX.md` 를 쓴다. 파일(또는 파일 안의 구역)마다 분류한다.

   | 파일 | 분류 | 내용 한 줄 | 어디로 |
   |---|---|---|---|
   | `과제안내.pdf` 1쪽 | 안내문 | 150분, 빌드 명령, 제출 방법 | `SUBMIT_RULES.md` |
   | `과제안내.pdf` 2쪽 | AI 사용 지침 | 대화 기록 전체 제출 | `AI_GUIDELINE.md` |
   | `problems.docx` 1~2쪽 | 문제 1 | 주문 상태 | `problems/p1/PROBLEM.md` |
   | `samples.zip` 의 `p1_sample.in/.out` | 문제 1의 예제 | | `problems/p1/given/`, `tests/01_example` |

   분류는 안내문 / AI 사용 지침 / 문제 k / 문제 k의 예제·자료 / 평가 기준 / 기타 가운데 하나다. 어느 문제의 것인지 모르는 파일은 "모름"이라 적고 사용자에게 묻는다.
4. `SUBMIT_RULES.md` 를 쓴다. 안내문에 적힌 것만 옮긴다(없는 칸은 "안내문에 없음"): 제출 파일 이름 규칙, 빌드 명령, 시간·메모리 제한, 제출 방법(받는 주소, 제목, 첨부 형식), 마감 시각, AI 사용 내역의 제출 형식, 질문할 수 있는지와 방법. 시간·메모리 제한이 안내문에 있으면 루트에 `limits.conf` 도 만든다(`TIME_SECONDS=1`, `MEMORY_MB=256` 처럼 한 줄에 하나. 안내문에 없는 것은 쓰지 않는다). `verify.sh` 가 이 값을 기준으로 쓴다. 빌드 명령이나 파일 이름이 `AGENTS.md` 의 "작업 조건"과 다르면 **안내문을 따르고 사용자에게 알린다.**
5. AI 사용 지침이 있으면 `AI_GUIDELINE.md` 로 저장하고 사용자에게 세 줄로 요약한다. 이 폴더의 규칙과 다르면 지침을 따른다.
6. 문제를 나눈다. 문제 번호는 **문제지의 번호를 그대로** 쓴다(문제지의 "문제 2"는 `p2`). 문제마다 `scripts/new_problem.sh pN` 을 부른다.
   - `problems/pN/PROBLEM.md` 에 원문을 **한 글자도 바꾸지 않고** 옮긴다. 번역하지 않는다(영어 문제는 영어 그대로). 표는 마크다운 표로 옮긴다.
   - 원본이 글 파일이 아니었으면(PDF, 워드, 한글, 그림) 원본을 `problems/pN/given/` 에 복사하고, `PROBLEM.md` 맨 위에 `<!-- 원본: given/파일이름, N쪽. 옮겨 적은 것 -->` 한 줄을 둔다.
   - 예제 파일이 따로 왔으면 `problems/pN/given/` 에 복사하고 `tests/01_example.in/.out` (여러 개면 `01a`, `01b` …)으로도 복사한다.
7. **옮겨 적기 확인(기계).** 문제마다 `scripts/transcribe_check.sh pN` 을 돌린다. `PROBLEM.md` 의 숫자, 기호, 대문자 낱말, 비교 낱말(이상·이하·초과·미만)을 원본에서 꺼낸 글과 견준다. 이 확인은 개수와 순서만 본다. 문장의 뜻(…이면, …일 때만, …않으면)은 보지 않으므로 **조건이 적힌 문장은 옮긴 뒤 원본과 한 번 더 대조**한다. "순서가 다른 곳"이 나오면 그 자리를 원본에서 다시 읽는다. `PROBLEM.md` 가 틀리면 답안도 독립 구현도 같은 틀린 글을 보고 함께 틀리므로, 사람에게 미루지 않고 여기서 잡는다.
   - "다른 것이 있다"면 원본을 다시 읽고 `PROBLEM.md` 를 고친 뒤 다시 돌린다. 표 머리처럼 옮기며 덧붙인 것이면 덧붙인 것을 뺀다.
   - "견줄 원본 글이 없습니다"(그림, 스캔한 PDF)면 **두 번째 읽기**를 한다: Agent 도구로 새 에이전트를 띄워 "원본 파일(경로)을 Read 로 읽고, 문제 k의 글 전체(문장, 표, 예제 입출력)를 보이는 그대로 `problems/pN/given/second_read.txt` 에 적어라. 요약하지 마라. 다른 파일은 읽지 마라"고 시킨다(네가 옮긴 `PROBLEM.md` 를 보여 주지 않는다). 끝나면 `scripts/transcribe_check.sh pN` 을 다시 돌린다.
   - 두 번 읽고도 다른 곳이 남으면 그 줄만 사용자에게 보여 주고 원본의 값을 묻는다. 그 밖에는 사람에게 확인을 부탁하지 않는다.
8. `scripts/log_step.sh "<모델>" "문제 N개 접수 (받은 파일 M개: 분류는 inbox/INDEX.md)"`

## 2. 다른 모델에게 애매한 점 묻기 (백그라운드)
문제마다 `scripts/codex_ask.sh ambig pN` 을 백그라운드로 돌린다. 기다리지 않고 3번으로 간다.
출력이 `CODEX_NOT_FOUND` 나 `CODEX_FAILED` 로 시작하면 `CLAUDE.md` 의 대비책을 쓴다.

## 3. 문제마다 SPEC 과 EDGE 쓰기
1. `SPEC.md`: 형식은 `templates/FORMATS.md`. 원문에 없는 것을 지어 넣지 않는다. **"크기와 시간" 절을 반드시 채운다**(최대 메시지 수, 값의 범위, 시간 제한).
2. `EDGE.md`: 두 가지를 차례로 대어 본다.
   - `CHECKLIST.md`: 입력이 깨졌을 때.
   - `knowledge/TRAPS.md`: 이 문제에 나오는 메시지 종류에 해당하는 절만. 순서와 뜻이 까다로운 경우다. 해당하는 항목은 근거 칸에 `T번호`를 적는다. **문제에 없는 기능을 이 사전을 보고 지어 넣지 않는다.**
   - 해당하는 항목마다 입력 예와 기대 출력을 적는다. 원문에 답이 없으면 기대 출력을 비워 두고 결정 대상으로 표시한다.
   - **원문이 어떤 명령에는 조건을 적고 다른 명령에는 적지 않았으면**(예: C 는 "LIVE 인 주문", CA 는 조건 없음) 그 차이를 행으로 적는다. 조건이 없는 쪽은 "원문 글자 그대로면 어느 상태에서든 처리"가 한 선택지다.
3. 네가 찾은 애매한 점마다 네 선택과 확신도를 `AMBIG_claude.md` 에 먼저 적어 둔다(Codex의 답을 보기 전에).

## 4. 결정하기
1. `AMBIG_codex.md` 가 도착하면 네 목록과 합친다. 한쪽만 찾은 것도 넣는다.
2. 각 항목을 `AGENTS.md` 의 기준으로 나눈다.
   - AI가 정한다: 두 모델의 선택이 같고 확신도가 높거나 중간이며 `AGENTS.md` 의 "추천을 고르는 기준"과 어긋나지 않는다 / 사람이 답할 근거가 없다(지어낸 오류 글자 등). AI가 정할 때도 그 기준을 따른다(값이 없으면 막는다, 통보는 버리지 않는다, 조용히 넘기지 않는다, 번호는 한 번만).
   - 사람에게 올린다: 선택이 다르다 / 확신도가 낮고 출력이 달라진다 / 틀리면 여러 줄이 한꺼번에 틀린다 / `TRAPS.md` 의 `갈림` 항목인데 문제에 답이 없다 / "추천을 고르는 기준"이 가리키는 쪽과 "원문 글자 그대로"가 다르다(3장 한도 안에서 가장 먼저 올린다).
3. `DECISIONS.md` 를 쓴다. 사람에게 올리는 것은 `templates/FORMATS.md` 의 결정 카드 형식으로, **문제당 3장까지**. 선택지 하나는 "원문 글자 그대로"다.
   - **"AI가 정한 것" 표의 첫 행은 늘 `D0 입력 나누기와 숫자 표기`다**(`templates/FORMATS.md` 의 기본값을 그대로 쓰고, 이 문제에서 달라지는 점만 고친다). 모든 문제에 같은 값을 쓴다. 답안, 독립 구현, 교차 확인이 공백이나 `+1`, `-0` 에서 갈려 시간을 쓰는 일을 막는다.
4. 구현 방법(자료형, 알고리즘)은 `## 구현 메모` 절에만 적는다. **"효율 계획" 표를 채운다**: 연산마다 자료구조와 메시지 하나당 시간, 가장 느려지는 입력, 근거. 이 표가 `gen_big` 과 리뷰의 기준이 된다.
   - `knowledge/PERF.md`(속도·메모리 사전)에서 이 문제에 나오는 것에 해당하는 절만 읽는다. 맨 위의 "크기로 고르기" 표에서 `SPEC.md` 의 최대 크기에 맞는 **가장 단순한** 구조를 고르고, 근거 칸에 `S번호`를 적는다.
   - "가장 느려지는 입력" 칸은 사전의 Z절(큰 입력 모양)에서 고른다. 해당하는 모양이 여럿이면 다 적는다.
   - 등급이 `[말]` 인 항목은 구현하지 않는다. 답안 맨 위 주석의 "실전이라면 더 바꿀 것"에 쓸 것만 표 아래에 한두 줄 적어 둔다.
   - 최대 크기가 원문에 없으면 줄 수 100만으로 어림하고, 그렇게 가정했다고 적는다.
5. `scripts/log_step.sh "<모델>" "pN SPEC, EDGE, DECISIONS 작성"`

## 5. 사람에게 한 번에 보여 주기 (기다리지 않는다)
아래를 한 메시지로 보여 준다. 한국어로 쓴다.

1. 문제별 한 줄 요약, 예상 난이도, 예상 시간(분), 권하는 풀이 순서(쉬운 것부터). 문제당 예산은 `scripts/board.sh` 에 나온다.
2. 사람에게 올린 결정 카드 전부(문제 순서, 영향이 큰 것부터). `DECISIONS.md` 의 카드를 그대로 보여 준다.
3. AI가 정한 것은 표로만 보여 준다(질문, 선택, 근거 한 줄). "확신 낮음"과 "지어낸 글자"는 표시한다.
4. 답하는 법과 다음 행동을 알린다.

   > 카드의 답을 기다리지 않습니다. **지금 바로** 문제마다 Claude Code 대화창을 하나씩 새로 열어 `/solve p1`, `/solve p2` … 를 시작해 주세요(문제가 하나면 이 창에서 `/solve p1`). 풀이는 추천안으로 먼저 진행합니다.
   > 카드는 풀이가 도는 동안 읽고, **풀이가 돌고 있어도 그대로** 그 문제의 창에 `D2: A, D3: B` 처럼 입력해 보내 주세요(하던 일이 끝나는 대로 읽습니다). "추천대로"도 됩니다. 추천과 다른 답은 그때 반영합니다(카드의 "나중에 바꾸는 비용"만큼 걸립니다).
   > 기대 출력이 맞는지는 사람이 보지 않아도 됩니다. 다른 모델이 문제만 보고 따로 구한 출력과 기계가 견줍니다.
   > 문제를 읽으며 걸린 것 가운데 위 목록에 없는 것이 있으면 말씀해 주세요.

5. 과제 안내문이 문제를 낸 쪽에 질문할 수 있다고 했으면 `templates/FORMATS.md` 의 안내대로 `logs/QUESTIONS.md` 를 쓰고 사용자에게 알린다. 안내문에 그런 말이 없으면 쓰지 않는다.

## 6. 이 창에서 답을 받았을 때
(답은 보통 `/solve` 창에서 받는다. 이 창에서 받으면 아래를 한다.)
1. **먼저** `scripts/log_step.sh "사람" "결정: p1-D2 A, p2-D1 B"` 로 사람의 답을 기록한다. 파일을 고치기 전에 한다.
2. 각 카드에 `- 결정: A (사람, 시각)` 을 덧붙인다. "추천대로"면 `- 결정: A (사람이 추천안을 승인, 시각)`. 사람이 새로 짚은 점은 카드나 AI 결정으로 추가하고 "사람이 찾음"이라고 적는다.
3. `EDGE.md` 의 비어 있던 기대 출력을 채우고 `scripts/log_step.sh "<모델>" "pN 결정 반영"`.
