# 질문 창: 기록에 남는 곁 질문

질문: $ARGUMENTS

사람은 일반 대화창 하나를 질문 전용으로 열고 `/ask <질문>` 을 친 뒤, 같은 창에서 이어서 묻는다.
이어서 묻는 글에도 이 규칙을 그대로 지킨다. 곁 질문(/btw)은 대화 기록에 남지 않지만 이 창은 남는다.

## 지킬 것
- **읽기만 한다.** 파일을 만들거나 고치지 않는다. `scripts/verify.sh`, `scripts/codex_ask.sh`, `scripts/log_step.sh`,
  `scripts/collect_logs.sh` 같은 스크립트를 돌리지 않는다. 파일 읽기와 `git log` 는 된다.
- 고쳐야 할 것이 보이면 직접 고치지 않고, 문제 창에 붙여 넣을 한 줄로 알려 준다.

## 읽을 것
질문에 나온 문제(`pN`)의 `problems/pN/` 에서 필요한 것만 읽는다.
`PROBLEM.md`(원문), `SPEC.md`(요구사항), `DECISIONS.md`(결정 카드), `REPORT.md`(보고서), `VERIFY.txt`(검증 결과).
문제 이름이 없으면 질문의 결정 번호나 낱말로 찾고, 그래도 모르면 어느 문제인지 한 줄로 묻는다.
원문의 문장이 답을 정하면 그 문장을 그대로 따옴표로 인용한다(`PROBLEM.md` 의 어디인지도).

## 답하는 법
읽는 사람은 파이썬에 익숙하다. 쉬운 한국어로, **12줄 안팎**으로 쓴다.
1. 첫 줄에 결론을 쓴다.
2. 선택지가 있으면 **사람 대신 정하지 않는다.** 선택지마다 "고르면 무엇이 어떻게 나오는가"를 한 줄씩 쓴다
   (가능하면 짧은 입력과 출력 예로).
3. `DECISIONS.md` 가 무엇을 권했는지 쓰고, 그 권고에 동의하는지와 이유를 한두 줄로 쓴다.
4. 모르는 것은 모른다고 쓴다. 특히 평가기가 무엇을 기대하는지는 원문에 없으면 알 수 없다. 추측이면 추측이라고 쓴다.
5. 마지막 줄에 사람이 그 문제의 창에 그대로 붙여 넣을 한 줄을 쓴다. 예: `p1 D3: C`
   (정할 것이 없는 설명 질문이면 이 줄은 `붙여 넣을 것 없음` 으로 쓴다.)

## 예 (모양만 본다. 내용은 지어낸 것이다)
```
결론: A 는 첫 접수 통보만 ACK 로 내고, C 는 통보마다 ACK 를 다시 내지만 주문 상태는 바꾸지 않는다.
원문: "같은 주문번호로 접수 통보가 다시 오면 ..." (PROBLEM.md 3절) — 다시 낼지는 적혀 있지 않다.
- A 를 고르면: 두 번째 통보에 아무것도 출력하지 않는다. 입력 `N 1`,`N 1` → `ACK 1`
- C 를 고르면: `ACK 1`,`ACK 1`. 상태는 처음 그대로다.
DECISIONS.md 는 C 를 권한다. 동의한다: 원문 표의 '통보마다 응답' 줄과 맞는다.
평가기가 두 번째 ACK 를 기대하는지는 원문만으로는 모른다.
붙여 넣을 것: p1 D3: C
```
