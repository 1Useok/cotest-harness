# 제출 준비

새 기능을 쓰지 않는다. 지금 있는 것을 확인하고 묶는다. 사용자에게 보이는 글은 한국어로 쓴다.

## 1. 최종 관문
문제마다 `scripts/final_gate.sh pN` 을 돌린다. 결과는 셋 중 하나다.
- **PASS**: `submit/pN.cpp` 로 복사된다.
- **조건부**: 복사되지 않는다. 이유(알려진 오답, 생략된 검사, 교차 확인에서 가리지 못한 사례, 느린 큰 입력 등)를 사용자에게 그대로 보여 주고 묻는다: "이 조건을 안고 제출합니까?" 사용자가 그렇다고 하면 **사용자가 한 말을 그대로** 넣어 `scripts/final_gate.sh pN --accept "<사용자의 말>"` 로 다시 돌린다. 네가 사유를 지어내 `--accept` 를 붙이지 않는다.
- **FAIL**: 고칠 수 있는지 5분 안에 판단한다. 못 고치면 **마지막으로 통과한 판**을 제출할지 사용자에게 묻는다(`git log` 에서 찾는다). 한 번도 통과한 판이 없으면 지금 상태를 낼지 사용자가 정하고, 무엇이 실패하는지 보고서에 적는다.

`SUBMIT_RULES.md` 에 제출 파일 이름 규칙이 있고 `pN.cpp` 와 다르면, `submit/` 안의 파일을 그 이름으로 **복사**한다(원래 이름의 것은 그대로 둔다). 무엇을 어떤 이름으로 복사했는지 사용자에게 알린다.

## 2. AI 사용 내역
1. `AI_USAGE.md` 의 맨 위 표(도구, 모델, 용도)를 실제로 쓴 것으로 채운다.
2. 문제마다 "AI가 한 일 / 사람이 한 일"을 적는다. 사람이 한 일은 `REPORT.md` 의 "사람이 한 일"에서 옮긴다(결정, 탐침, 받아들인 한계). **사람이 하지 않은 일을 적지 않는다.** 사람의 입력은 `submit/ai_usage/02_human_inputs.md` 에 기계로 뽑혀 나오므로 그것과 어긋나면 안 된다.
3. 대화창마다 `/export` 를 쳐 달라고 하지 않는다. 읽기 쉬운 대화 기록은 `scripts/pack.sh` 가 원본 기록에서 만든다.

## 3. 제출 묶음 만들기
`scripts/pack.sh` 를 돌린다. 원본 기록을 다시 모으고, 세 가지를 만든다.
- `submit/ai_usage_logs.zip`: AI 사용 내역, 대화 기록(원본과 읽기 쉬운 것), 문제별 결정·보고서·검증 결과·테스트.
- `submit/ai_usage/`: 같은 내용을 여러 형식으로 풀어 둔 폴더(전체 한 파일의 글·워드·웹 문서, 창별, 문제별, 사람이 입력한 것만, 주고받은 일의 표, 도구와 모델 표).
- `submit/SUBMIT_LIST.md`: 첨부할 것과, 안내문이 다른 형식을 요구할 때 어느 파일을 낼지의 표.

그다음에 한다.
- "보내기 전에 확인할 것"에 굵은 글씨가 있으면(답안 없음, 원본 기록 없음, 대화 기록을 만들지 못함) 그것부터 해결하고 다시 돌린다.
- `submit/ai_usage/00_README.md` 의 개수(창 수, 사람 입력 수, 모델)가 실제와 맞는지 본다. `01_tools_and_models.md` 의 모델 이름을 `AI_USAGE.md` 맨 위 표에 그대로 옮긴다(짐작해서 적지 않는다).
- **`AI_GUIDELINE.md` 와 `SUBMIT_RULES.md` 의 "AI 사용 내역 제출 형식"을 다시 읽고, 요구한 형식과 `SUBMIT_LIST.md` 의 표를 맞춰 "이 과제에서 낼 파일"을 정한다.** 요구가 표에 없는 형식이면(정해진 양식, 특정 파일 이름, 한 파일로 합치기 등) `submit/ai_usage/` 의 파일과 `sessions.json` 을 재료로 그 형식의 파일을 만들어 `submit/` 에 둔다. 내용을 새로 지어 쓰지 않는다. 기록에 있는 것을 옮긴다.
- 지침이 형식을 정하지 않았으면 `ai_usage_logs.zip` 하나를 낸다.

## 4. 제출 목록 보여 주기
`scripts/board.sh` 를 돌리고 아래를 표로 보여 준다.
- **메일에 첨부할 것**: `submit/SUBMIT_LIST.md` 의 표 그대로(답안 파일들, `ai_usage_logs.zip`). 과제 안내문이 다른 형식을 요구하면(`SUBMIT_RULES.md`) 그것을 먼저 적는다.
- 문제별 판정(조건부면 사람이 받아들인 사유)과 숫자: 정답 사례(다른 모델이 따로 구한 출력과 같은 수), 무작위 비교, 변형, 큰 입력 시간, 알려진 한계
- 검증이 놓칠 수 있는 것

## 5. 기록
`scripts/log_step.sh "<모델>" "제출 준비 완료: p1 PASS, p2 조건부(사람 승인) ..."`

마지막으로 사용자에게 알린다: "메일을 보내기 직전에 터미널에서 `scripts/pack.sh` 를 한 번 더 돌려 주세요. 이 응답까지 기록에 들어갑니다. 그 뒤 `submit/` 의 답안 파일과 AI 사용 내역(위에서 정한 파일. 정해진 형식이 없으면 `ai_usage_logs.zip`)을 첨부하면 됩니다."
제출 메일은 사용자가 직접 보낸다. 메일을 대신 쓰거나 보내지 않는다.
