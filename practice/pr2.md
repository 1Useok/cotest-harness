# 연습 2. 주문 상태와 취소·정정

주문 하나하나의 상태를 관리하는 프로그램을 작성하라. 표준 입력의 메시지를 한 줄씩 처리하고, 메시지마다 결과를 한 줄 출력한다.
메시지는 우리가 거래소로 보낸 **요청**과 거래소가 보내온 **통보**가 섞여 있다.

## 입력

필드는 공백 하나로 나뉜다. 번호와 수량, 가격은 1 이상 1,000,000 이하의 정수다.

| 메시지 | 뜻 |
|---|---|
| `N <주문번호> <B 또는 S> <수량> <가격>` | 신규 주문 요청 |
| `C <주문번호>` | 취소 요청 |
| `CA <주문번호>` | 거래소의 취소 확인 |
| `CR <주문번호>` | 거래소의 취소 거부 |
| `R <주문번호> <새 수량>` | 수량 정정. 새 수량은 이미 체결된 수량을 포함한 총수량이다 |
| `F <주문번호> <수량> <가격>` | 거래소의 체결 통보 |
| `Q <주문번호>` | 상태 조회 |

## 상태

주문의 상태는 `LIVE`(살아 있음), `PENDING_CANCEL`(취소 요청을 보내고 답을 기다리는 중), `FILLED`(전량 체결), `CANCELED`(취소됨) 가운데 하나다.

## 처리와 출력

1. **신규** `N`: 처음 보는 주문번호면 주문을 `LIVE` 로 등록하고 `ACK <주문번호>` 를 출력한다. 이미 있는 번호면 `REJ <주문번호> DUP` 을 출력한다.
2. **취소 요청** `C`: `LIVE` 인 주문을 `PENDING_CANCEL` 로 바꾸고 `PEND <주문번호>` 를 출력한다.
3. **취소 확인** `CA`: 남은 수량을 모두 취소하고 상태를 `CANCELED` 로 바꾼다. `CXL <주문번호> <취소된 수량>` 을 출력한다.
4. **취소 거부** `CR`: `PENDING_CANCEL` 인 주문을 `LIVE` 로 되돌리고 `CXLREJ <주문번호>` 를 출력한다.
5. **체결** `F`: 체결 수량이 남은 수량보다 많으면 `ERR <주문번호> OVERFILL` 을 출력하고 반영하지 않는다. 아니면 반영하고 `FILL <주문번호> <누적 체결 수량> <남은 수량>` 을 출력한다. 남은 수량이 0이 되면 상태는 `FILLED` 다. **취소 요청을 보낸 뒤 답이 오기 전에 도착한 체결은 반영한다.** 이때 남은 수량이 0이 되지 않았다면 상태는 `PENDING_CANCEL` 그대로다.
6. **정정** `R`: `LIVE` 인 주문의 총수량을 새 수량으로 바꾸고 `RPL <주문번호> <남은 수량>` 을 출력한다.
7. **조회** `Q`: `STATE <주문번호> <상태> <누적 체결 수량> <남은 수량>` 을 출력한다. `CANCELED` 인 주문의 남은 수량은 0이다.

## 예제

입력
```
N 1 B 10 100
F 1 3 100
C 1
F 1 2 101
CA 1
Q 1
N 2 S 4 50
C 2
CR 2
R 2 6
F 2 6 50
Q 2
```

출력
```
ACK 1
FILL 1 3 7
PEND 1
FILL 1 5 5
CXL 1 5
STATE 1 CANCELED 5 0
ACK 2
PEND 2
CXLREJ 2
RPL 2 6
FILL 2 6 0
STATE 2 FILLED 6 0
```
